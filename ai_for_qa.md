MCP Chrome dev tools
- Создать `opencode.json` в ~/.opencode для глобального применения или в корне проекта для локального
```
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "chrome-devtools": {
      "type": "local",
      "command": ["npx", "-y", "chrome-devtools-mcp@latest"]
    }
  }
}
```
MCP Postgresql  
Добавьте в конфиг в блок mcp, заменив user/pass/host/port/database

```
    "postgres": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-postgres", "postgresql://user:pass@host:port/database?sslmode=disable"]
    }
```
или

`opencode mcp add postgres-connection --label "PostgreSQL" --command "npx" --args "-y","@modelcontextprotocol/server-postgres","postgresql://user:pass@host:port/database?sslmode=disable"`

# 🚀 Руководство по использованию AI-агентов для написания автотестов

Это не просто список советов, а методология работы. Использование AI для кода — это скилл, требующий правильного фреймворка мышления. Ниже — синтез практического опыта и лучших мировых практик по работе с LLM (Large Language Models) в контексте автоматизации тестирования.

## 1. Стратегия планирования: Разделяй и властвуй

Главная ошибка новичков — пытаться «заставить» агента написать весь проект сразу. Это приводит к «каше» в контексте и плохому коду.

- **Plane mode прежде всего:** Работайте в режиме планирования (Plane/Ask mode), пока не зафиксируете точное ТЗ. *Почему это важно:* В режиме планирования агент не тратит ресурсы на правку файлов, он только рассуждает. Это экономит лимиты и время. Вносите правки в текст задачи, пока формулировка не станет идеальной.
- **Атомарность задач:** Дробите задачу на мелкие куски. Вместо «Напиши тесты на корзину» просите: «Добавь тест на добавление товара в пустую корзину».
- **Тестовые данные:** Четко указывайте, какие данные использовать — статические, генерируемые или из фикстур. Агент должен понимать, откуда брать значения для полей, и как они влияют на повторяемость теста.

## 2. Контекст — это ваша валюта

Контекстное окно модели (Context Window) — это её кратковременная память. Ваша задача — тратить её максимально эффективно.

- **Принцип точечного контекста:** Не просите «посмотри проект». Используйте **@file** для указания конкретных файлов (Page Object, утилиты, фикстуры). Это снижает шум.
- **Правило «Одной сессии»:** Если вы решили задачу А и переходите к задаче Б, начинайте **новый чат (сессию)**.
  - *Опасность:* Старые диалоги и старый код в контексте действуют как «якорь». Агент начинает путать переменные или использовать старые локаторы.
  - *Метрика:* Опасайтесь приближения к лимиту контекста. Как только занято ~85–90% лимита, модель может начать «сжимать» историю, теряя критически важные детали (это вызывает галлюцинации).
- **Закрепление правил (AGENTS.md):** Создайте файл правил. В запросе используйте `@AGENTS.md`. Это ваш «устав» проекта для робота.

## 3. Воркфлоу разработки теста (Best Practices)

Идеальный цикл создания теста с помощью AI выглядит так:

**Шаг 1. Заготовка (Skeleton)**
- Создайте файл вручную или дайте агенту пример (`example.spec.ts`).
- **Запрос:** «Создай файл `login.spec.ts` по подобию `@registration.spec.ts`, но для сценария логина. Импортируй нужные классы из `@pages`».

**Шаг 2. Черновой код (Draft)**
- Включите Build/Agent Mode.
- Опишите шаги сценария списком. Не давайте агенту свободу в выборе селекторов, если не уверены в нём.

**Шаг 3. Итеративное улучшение (Refactoring)**
- **Не откатывайтесь сразу.** Если код «почти работает», не просите переписать с нуля (это лишний расход токенов).
- Лучше: «Строка 15: замени жесткий sleep на явное ожидание `expect(locator).toBeVisible()`».
- Просите агента запустить тест. Если он путает команды, дайте ему подсказку: «Команда для запуска описана в `package.json`, используй `npm run test -- login`».

**Шаг 4. Ревью (Review & Style)**
- После того как тест «зеленый», попросите привести его к стандартам.
- **Промпт:** «Сделай ревью кода. Используй лучшие практики и паттерны из @AGENTS.md. Оптимизируй импорты и проверь читаемость».

## 4. Работа с UI и DOM (Специфика тестирования)

- **Поиск локаторов:** Если проект большой, не давайте агенту полагаться на память.
  - *Запрос:* «Изучи DOM фрагмента (вставьте HTML сюда). Найди самый стабильный XPath/CSS для кнопки "Оплатить"».
- **Снижение флаки тестов:** Введите правило в AGENTS.md: «Никогда не используй `sleep` или `waitForTimeout`. Используй `waitForResponse` или `expect.poll`».
- **Использование MCP Chrome DevTools:** Для более глубокого взаимодействия с браузером подключите MCP-сервер Chrome DevTools.
  - **Что это даёт:** Агент получает прямой доступ к вкладкам браузера, может инспектировать DOM в реальном времени, выполнять JavaScript, просматривать сетевые запросы и консольные сообщения.
  - **Когда полезно:**
    - Отладка динамического контента, который появляется после асинхронных операций.
    - Проверка, какой именно запрос отправляется при клике (для создания стабильных ожиданий).
    - Поиск скрытых элементов или анализ сложных CSS-правил.
  - **Как использовать:** Попросите агента: «Подключись к Chrome DevTools MCP, открой страницу `https://...`, выполни поиск элемента с текстом "Submit" и верни его точный селектор».
  - **Преимущества:** Уменьшает количество итераций на уточнение локаторов, позволяет агенту самостоятельно исследовать UI, а не полагаться на ваши описания.

## 5. Контроль версий и Git

Использование Git — это ваш «стоп-кран» и инструмент аудита.

- **До:** Сделайте коммит чистого состояния.
- **После:** Используйте `git diff`. Смотрите, что именно изменил агент. Это помогает учиться и замечать странные правки.
- *Совет:* Просите агента писать осмысленные commit message, соответствующие Conventional Commits.

## 6. Self-Correction и остановка генерации

Умение вовремя остановить агента — критически важный навык.

- **Распознавание галлюцинаций:** Если в рассуждениях агента видите несуществующие методы библиотеки (например, он придумал `page.clickByText` в Playwright, хотя там `getByText`), немедленно останавливайте.
- **Инъекция уточнения:** Напишите: «Стоп. В версии библиотеки, которую мы используем, нет метода X. Используй Y».

## 7. Накопление базы знаний (Knowledge Base)

Самый ценный для долгосрочной перспективы навык — фиксировать полученный опыт.

- **Пост-анализ:** Если вы потратили 5 итераций, чтобы объяснить агенту, как обходить OAuth-авторизацию в тестах — **запишите это в `AGENTS.md`**.
- **Структура правил:**
  1. *Стек:* (Playwright + TS + Fixtures).
  2. *Запреты:* (Не использовать XPath, не хардкодить URL).
  3. *Паттерны:* (Использовать `async/await`, Page Object Model).
  4. *Запуск:* (Как запускать конкретный тест).

## Чек-лист идеального промпта для агента

Чтобы получить идеальный код с первого раза, используйте структуру **CRAFT**:

1. **Context (Контекст):** «Мы пишем e2e тесты для интернет-магазина...» + `@AGENTS.md` + `@page.ts`.
2. **Role (Роль):** «Ты — senior SDET (Automation QA Engineer)».
3. **Action (Действие):** «Напиши тест, который проверяет...».
4. **Format (Формат):** «Используй Page Object, код оформи в классе...».
5. **Target (Цель):** «Тест должен проходить в headless режиме без задержек».

### Вывод

Агент — это **Junior-разработчик с феноменальной скоростью печати, но нулевым пониманием контекста вашего бизнеса**. Ваша задача — быть тимлидом: ставить четкие задачи, выдавать вводные и проверять результат через Git.
